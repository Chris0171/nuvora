# NUVORA — PROJECT STATE REPORT

## 1. RESUMEN GENERAL DEL PROYECTO

- Estado actual de Flutter:
	Proyecto Flutter multiplataforma con MaterialApp, Material 3 habilitado en ThemeData y ProviderScope global.
- Arquitectura utilizada:
	Feature-first con separación parcial en presentation / application/controllers / domain / data.
- Gestión de estado:
	Riverpod con Provider, FutureProvider y un StateProvider para la búsqueda de notas.
- Persistencia:
	Persistencia local SQLite implementada de forma real para Tasks, Notes y Reminders.
- Base de datos:
	Tres bases SQLite separadas por feature: `nuvora_tasks.db`, `nuvora_notes.db`, `nuvora_reminders.db`.
- Navegación:
	AppShell con IndexedStack y barra de navegación inferior personalizada para Home, Tasks, Notes, Insights y Settings.
- Sistema de temas:
	Hay dos capas coexistiendo: ThemeData en `core/theme/app_theme.dart` y un design system de uso masivo en `core/theme/app_design_system.dart`.
- Soporte light/dark:
	Light/dark definido en MaterialApp, pero la UI usa en gran parte colores fijos del design system, así que el dark mode no está aplicado de forma consistente en todas las pantallas.
- Plataformas objetivo:
	Android, iOS, Web, Linux, macOS y Windows por la estructura real del proyecto.
- Dependencias principales:
	Flutter, flutter_riverpod, sqflite, sqflite_common_ffi, path, uuid.
- Estado actual de tests:
	196 tests pasando.
- Estado de flutter analyze:
	Limpio, sin issues.

## 7. INSIGHTS

Insights utiliza datos reales de Tasks/Notes, pero sigue siendo una feature parcial, muy visual y sin backend propio.

Qué métricas son reales:
- Completion rate.
- Completed count.
- Pending count.
- Notes count.
- Completed this week.
- Notes created this week.
- Streak actual basada en tareas completadas hoy.

Qué métricas son calculadas:
- Productivity score.
- Consistency level.
- Weekly productivity.
- Focus label mostrado en Productivity Cards.

Qué gráficos son reales:
- El gráfico weekly bars se genera a partir de valores calculados reales de Tasks y Notes.
- Score ring usa score calculado real.

Qué gráficos son mock:
- No son mock puros, pero son visualizaciones derivadas sin una capa analítica propia ni histórico persistido.

Qué datos están hardcodeados:
- Textos de recomendaciones.
- Estructura visual de placeholders.
- CTA “Generate first insights”.

Qué habría que implementar para convertir Insights en una feature real:
- Persistencia histórica de métricas.
- Modelo/dominio propio de insights.
- Filtros temporales reales.
- Possibly snapshots diarios/semanales.
- Cobertura de tests propia.
